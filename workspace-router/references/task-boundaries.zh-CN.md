# 任务分界 · 1.3 推荐默认

[三套预设与实测依据](presets.zh-CN.md)

[English](task-boundaries.md) | **简体中文**

这套规则选择的是**确有必要的子代理**，不切换主模型，不会拦截每条消息。先判断是否值得委派，再按以下条件选择最高适用档。

| 档位 | 默认模型 / 强度 | 严格条件 | 示例 |
|---|---|---|---|
| 确定性任务 | Luna / High | **全部满足**：输入仅文本、提取或转换、规则精确、机械验收、局部范围、低影响、低不确定性 | 按固定字段批量提取、按明确映射转换文档 |
| 常规任务 | Sol / Medium | 没有命中更高档，需求和验收明确 | 局部功能实现、有明确复现与测试的修复、常规资料核对 |
| 复杂分析 | Sol / High | **任一满足**：跨组件或系统范围、需求开放、不确定性高、调试/复核/设计需要判断、主代理声明为复杂档 | 跨模块状态错误、并发故障定位、数学或坐标变换复核 |
| 高影响 / 系统设计 | Astra / High | **任一满足**：出错后果严重；系统范围且需求开放或不确定性高；主代理声明为关键档 | 高影响生产迁移复核、约束未定的系统架构 |

命中多档取最高档。已有的复杂度声明是最低档位，不能被表面简单的局部步骤降级。只有已诊断的推理/验证失败允许最多升一档恢复；网络、权限、模型不可用等问题先解决环境。

默认同时 **1** 个子代理，每个请求累计 **2** 次启动，最多 **1** 次恢复，预计纯推理工作量至少 **5 分钟**。等待下载、运行测试的时间不算推理工作量，也不能为启动代理夸大估计。这个门槛是控制交接开销的工程选择，不是测得的省钱比例。

## 判断依据

主代理需在 `task.assessment` 提供以下字段；该表的默认模型对应稳定方案：

| 字段 | 可选值与含义 |
|---|---|
| `kind` | `extract` 提取、`transform` 转换、`implement` 实现、`debug` 调试、`review` 复核、`research` 研究、`design` 设计 |
| `specification` | `exact` 规则和边界已规定；`bounded` 需求明确但有实现选择；`open` 关键需求或设计未定 |
| `verification` | `deterministic` 可按精确规则验收；`tests` 有实质性测试/行为检查；`judgment` 需要推理、解释或视觉判断 |
| `scope` | `local` 单个有明确边界的组件/文档集合；`cross_component` 多组件相互作用；`system` 系统级约束和接口 |
| `input_form` | `text` 不需要视觉识别（包括代码）；`visual` 图片、OCR 或需要视觉判断 |
| `boundary` | `clear` 边界明确；`adjacent` 有具体依据的相邻档位模糊，须额外提供非空 `boundary_evidence` |
| `evidence` | 用事实说明需求、验收、范围和风险，不写“任务简单”“适合并行”等空泛结论 |

风险和不确定性沿用 `task.consequence`、`task.uncertainty`。高影响指错误可能实质影响安全、资金、不可逆数据损失或访问控制；不能只见到某个领域关键词就认定高影响。风险未知应先调查，不能随意填低风险。

跨文件不等于跨组件：对大量文件应用同一个精确映射，仍可能是局部确定性任务。存在测试也不等于机械验收：如果需要判断测试是否遗漏关键约束，应标为需要判断的复核。

缺少评估依据时不自动派发；程序只能检查结构和规则，无法证明主代理填写的判断是真的，也不会额外调用一个模型来给自然语言任务分类。

## 回退顺序

- 确定性：Luna/High → Sol/Medium → Astra/Low。
- 常规：Sol/Medium → Astra/Medium。
- 复杂：Sol/High → Sol/Extra high → Astra/High。
- 关键：Astra/High → Astra/Extra high；不自动换成其他模型。

每一步都要由当前主机确认模型和强度可用。关键档没有合适候选时交回主代理并说明限制；这不表示主代理的模型自动满足质量要求，关键验收前仍需解决限制。回退列表是默认候选，不代表不同模型/强度有经验证的等价能力。

Terra、旧版 Sol 保留明确手动选择，不默认承担任务。Max 只接受明确且受支持的请求，Ultra 属于单独原生流程。浏览器和电脑的共享操作、外部副作用仍由主任务处理；选择更强模型不会自动获得插件或 SSH 权限。

## 研究依据

于 **2026-09-23** 核对：[Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) 的集中、高频任务定位；[Sol](https://developers.openai.com/api/docs/models/gpt-6-sol) 的编程和代理工作定位；[Astra](https://developers.openai.com/api/docs/models/gpt-6-astra) 的高难度端到端工作定位。

[Codex 子代理文档](https://learn.chatgpt.com/docs/agent-configuration/subagents) 给出的显式强度起点包含 Luna/High、Sol/Medium；本方案为复杂复核和高影响工作提高强度。[模型选择指南](https://learn.chatgpt.com/docs/model-selection) 建议用相同输入实测，并保留能达到质量门槛的较轻配置。[Terra 文档](https://developers.openai.com/api/docs/models/gpt-5.6-terra) 将其定位为上一代兼顾智能与成本的模型，未提供它应优先于当前 Sol 的本任务证据。

**严格的是规则，不是模型能力的绝对边界。** 四档条件、五分钟门槛、候选顺序是我们的工程默认；本版本没有运行付费的跨模型质量基准，也不声称节省某个比例的订阅额度。自动测试验证的是分流行为，不是模型答案正确率。

`default-policy.json` 保存推荐默认，`policy.json` 保存当前配置。控制台的 **恢复推荐默认** 会把整套模型和规则载入草稿，确认应用后生效。普通用户无需逐项设置。
